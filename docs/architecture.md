# Architecture: where things are

Update this when a folder or entry file is added, moved or removed. The planned layout is in `docs/plans/literature-feed.md` (Files of each phase); this page lists only what exists.

- `src/main.ts`: plugin entry. Loads the settings (`normaliseSettings`), moves old plain-text keys into Obsidian's secret storage (`migrateLegacyKeys`), hands out key values (`getSecret`), saves the settings, adds the settings tab, registers the **Scan now** command and the `literature-feed` block, reloads on an external `data.json` change (Phases 3 and 4).
- `src/inbox/`: `write.ts` the note (score into papers, render, read ticks back, add to an existing note; pure, tested), `scan.ts` one scan over all enabled feeds (window, seen list, failures; client injected, pure), `block.ts` the `literature-feed` code block (status line and Home card; Obsidian). `src/main.ts` runs the scan (**Scan now**) and writes the note with `vault.process`.
- `src/zotero/`: `client.ts` Zotero Web API v3 client (collections, search by DOI or title, create item, add collections and tag; pure, HTTP function injected), `map.ts` OpenAlex work to Zotero item (pure), `request.ts` the one wrapper around `requestUrl`, `collections-modal.ts` the read-only window of the command **Show Zotero collections**. `src/inbox/sync.ts` sends the ticked papers (pure; both clients injected); `main.ts` has the command **Sync ticked papers**.
- `src/settings/`: `data.ts` settings and feed types, tolerant loader, feed JSON import / export, editor warnings (pure, tested); `tab.ts` the settings tab (declarative API: `getSettingDefinitions`); `feed-modal.ts` the confirm, feed editor and import windows; `test-feed.ts` the editor's Test (one scan, scored and counted; pure). UI files are not unit-tested; they are checked by hand in `test-vault`.
- `docs/feeds/`: importable feed files (`lipoic-acid-copolymers.json`, the first feed).
- `src/match/`: the matching engine, pure (no Obsidian imports; a test checks). `feed.ts` types, `score.ts` text normalisation, both spellings, phrase match and the tier rules, `dedupe.ts` DOI then title, journal over preprint (Phase 1).
- `src/openalex/client.ts`: OpenAlex client (Phase 2). No Obsidian imports: the caller passes in a `Requester` and a `sleep`. Builds the search URL, pages, backs off on 429, sums `meta.cost_usd`, maps works to `Candidate` (a `Paper` plus authors, venue, OpenAlex id). Used by the feed editor's Test button and by **Scan now**; the weekly schedule is not wired in yet. `request.ts` is the one file that wraps Obsidian's `requestUrl` into the client's `Requester`.
- `scripts/openalex-run.mjs`: the real run against the live API (needs `OPENALEX_API_KEY`); bundles the client with esbuild, prints count and cost per topic, writes nothing. Not part of the plugin.
- `tests/`: vitest. `tests/openalex.test.ts` tests the client with `tests/fixtures/openalex-responses.ts` (hand-written) and `tests/fixtures/openalex-recorded.json` (one real work, authors replaced). `tests/score.test.ts` and `tests/dedupe.test.ts` test the engine; `tests/fixtures/` holds the lipoic acid feed and hand-written paper cases with a known tier each. `tests/helpers/obsidian-stub.ts` is the runtime stand-in for the `obsidian` package.
- `test-vault/`: dev vault. Only `Welcome.md` is tracked.
