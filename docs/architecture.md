# Architecture: where things are

Update this when a folder or entry file is added, moved or removed. The planned layout is in `docs/plans/literature-feed.md` (Files of each phase); this page lists only what exists.

- `src/main.ts`: plugin entry (also `refreshInbox`: Read links and archiving of finished inbox notes). Loads the settings (`normaliseSettings`), moves old plain-text keys into Obsidian's secret storage (`migrateLegacyKeys`), hands out key values (`getSecret`), saves the settings, adds the settings tab, registers the **Scan now** command and the `literature-feed` block, reloads on an external `data.json` change (Phases 3 and 4).
- `src/inbox/`: `write.ts` the note (score into papers, render, read ticks back, add to an existing note; pure, tested), `scan.ts` one scan over all enabled feeds (window, seen list, failures; client injected, pure), `table.ts` what the table shows (status of a paper, order, filter, ages-out window, takeaway filled; pure), `cards.ts` the models behind the per-search cards and the Home card's summary (counts, funnel, bar widths, papers to read, `limit`; pure), `state.ts` read state and archive rules (literature note index and match, week arithmetic, "is this note finished"; pure), `block.ts` the `literature-feed` code block (status line, cards, table and Home card; Obsidian). `src/main.ts` runs the scan (**Scan now**) and writes the note with `vault.process`.
- `src/zotero/`: `client.ts` Zotero Web API v3 client (collections, search by DOI or title, create item, add collections and tag; pure, HTTP function injected), `map.ts` OpenAlex work to Zotero item (pure), `request.ts` the one wrapper around `requestUrl`, `collections-modal.ts` the read-only window of the command **Show Zotero collections**. `src/inbox/sync.ts` sends the ticked papers (pure; both clients injected); `main.ts` has the command **Sync ticked papers**.
- `src/settings/`: `data.ts` settings and feed types, tolerant loader, feed JSON import / export, editor warnings (pure, tested); `tab.ts` the settings tab (declarative API: `getSettingDefinitions`); `feed-modal.ts` the confirm, feed editor and import windows; `test-feed.ts` the editor's Test (one scan, scored and counted; pure). UI files are not unit-tested; they are checked by hand in `test-vault`.
- `docs/feeds/`: importable feed files (`lipoic-acid-copolymers.json`, the first feed).
- `src/match/`: the matching engine, pure (no Obsidian imports; a test checks). `feed.ts` types, `score.ts` text normalisation, both spellings, phrase match and the tier rules, `dedupe.ts` DOI then title, journal over preprint (Phase 1).
- `src/openalex/client.ts`: OpenAlex client (Phase 2). No Obsidian imports: the caller passes in a `Requester` and a `sleep`. Builds the search URL, pages, backs off on 429, sums `meta.cost_usd`, maps works to `Candidate` (a `Paper` plus authors, venue, OpenAlex id). Used by the feed editor's Test button and by **Scan now**; the weekly schedule is not wired in yet. `request.ts` is the one file that wraps Obsidian's `requestUrl` into the client's `Requester`.
- `src/setup/`: Check setup: `checks.ts` the rows (keys, folders, search, project against notes, ZotLit, Lab Kit; pure, fixes are data), `integrate.ts` the three additions to Lab Kit's notes as text in, text out, found again by the tile's title link or the section's heading, no marker comments (plan, add, remove; pure), `setup-modal.ts` the window (Obsidian). `main.ts` builds the snapshot of the vault and carries out a fix.
- `src/prompts/`: the LLM prompt features, copy and paste only (no network): `schemas.ts` the three answer formats, their examples and validators (`extractJson` finds the JSON in a chat reply), `build.ts` the three prompt builders and the ledger numbers they print, `apply.ts` applying suggestions to a feed (`applySuggestions`, `describeSuggestion`), `decisions.ts` the approved/denied data set (`decisions.json`), `modals.ts` the two windows (prompt, then answer; Obsidian). All but `modals.ts` are pure.
- `src/menu.ts`: every command id with its group (Watch, Discover, Expand, Improve, Tools) and the ribbon **Find papers** menu as data (`COMMANDS`, `commandName`, `buildMenu`; pure). `main.ts` names its commands from it and draws the menu; `tests/menu.test.ts` fails if a registered command is missing from the list.
- `src/schedule.ts`: when the weekly scan and the daily sync are due (`latestScanDay`, `scanDue`, `syncDue`; pure). `main.ts` runs `checkSchedule()` after the layout is ready (15 s) and hourly, once a day per kind, with a quiet mode for `scanNow(auto)` and `syncNow(auto)`.
- `src/review/`: the literature review: `budget.ts` estimate, caps, running cost and the monthly tally, `cache.ts` the 24-hour result cache, `collect.ts` count/plan/run within the budget (score with each search's rules, merge searches), `flags.ts` in Zotero / in the vault / listed before, `prompt.ts` the prompt and the check of the pasted answer, `note.ts` the review note, `network.ts` the citation network, missing and citing works, citation gaps of one paper and the charts' numbers, `network-fetch.ts` the budgeted OpenAlex requests for them, `network-text.ts` the network for the prompt and the note (labels P, M, C), `canvas.ts` the Obsidian canvas file, `chart.ts` the chart specs (all pure), `chart-view.ts` draws a chart as SVG and is the `literature-feed-chart` code block, `layout.ts` the deterministic force-directed layout (each group of papers on its own), `timeline.ts` the timeline layout (year on the vertical axis) and `graph-data.ts` the graph as data (pure), `graph-view.ts` the graph tab (SVG, Obsidian), `window.ts` the review panel (Obsidian), `review-view.ts` the tab that holds it, `session.ts` the saved review in progress (pure), `src/refs/` (`split.ts` splits pasted references and reads their parts, `match.ts` judges a Crossref record against a reference, `crossref.ts` the Crossref client, `resolve.ts` the look-up of a whole list, `export.ts` the text outputs, all pure; `panel.ts`, `view.ts`, `request.ts` the tab, Obsidian), `gaps-input.ts` (what the gaps tool is asked about, the Zotero search, the estimate), `gaps-fetch.ts` (its budgeted OpenAlex requests), `gaps-note.ts`, `gaps-panel.ts` and `gaps-view.ts` (the tab; Obsidian), `record.ts` the record of how a review was made, its note section and block, and the comparison with a repeat (pure). The graph of the last review is kept in `review-graph.json` in the plugin folder. `src/zotero/library-index.ts` is the local Zotero index (pure, format 2: items with their collection keys, and the collection list), filled by `ZoteroClient.listLibraryItems`, `listDeleted` and `listCollectionsRaw` (one after another, in `refreshZoteroIndex`); `known.ts` works out a search's seed collection and known papers from it (pure); the OpenAlex client gained `countTopic`, `searchPage`, `getWorks`, `citingPage` and the optional citation fields. Files in the plugin folder: `refs-session.json`, `gaps-session.json`, `review-session.json`, `review-cache.json`, `zotero-index.json`, `openalex-spend.json`.
- `src/ledger/overlap.ts` (pure, with the ledger): overlap between searches (papers both list, papers one search's rules dropped that another lists; from `droppedIds`) and between the topics of one search, with the plain sentences and their Markdown; part of `report.ts`.
- `src/ledger/`: `ledger.ts` the long-term record (papers with their outcome days, scan log, numbered rule versions, reading a stored file tolerantly, `verdictOf`; pure), `report.ts` the per-search report model and its Markdown (pure), `report-modal.ts` the window (Obsidian). `main.ts` reads and writes `ledger.json` in the plugin folder with the vault adapter, records scans in `scanNow` and fills papers in `refreshInbox` (and in the report command), including notes in the archive folder.
- `scripts/make-demo.mjs`: `npm run demo`; bundles `src/inbox/write.ts` with esbuild and writes the demo set into `test-vault/Demo/` (or `--out DIR`, used by `tests/demo.test.ts`). Not part of the plugin.
- `scripts/openalex-run.mjs`: the real run against the live API (needs `OPENALEX_API_KEY`); bundles the client with esbuild, prints count and cost per topic, writes nothing. Not part of the plugin.
- `tests/`: vitest. `tests/openalex.test.ts` tests the client with `tests/fixtures/openalex-responses.ts` (hand-written) and `tests/fixtures/openalex-recorded.json` (one real work, authors replaced). `tests/score.test.ts` and `tests/dedupe.test.ts` test the engine; `tests/fixtures/` holds the lipoic acid feed and hand-written paper cases with a known tier each. `tests/helpers/obsidian-stub.ts` is the runtime stand-in for the `obsidian` package.
- `test-vault/`: dev vault. Only `Welcome.md` is tracked.
